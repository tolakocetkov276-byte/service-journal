# Журнал обслуживания техники

Учебный проект Анатолия Валерьевича на Python и SQLite.
Есть терминальная версия и веб-интерфейс на Flask. Обе используют одну базу.

## Веб-интерфейс

На Windows в папке проекта выполните:

```text
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

После первой установки можно запускать `Start-Web.cmd`.
Откройте http://127.0.0.1:5055. Чтобы остановить сервер, нажмите Ctrl+C
в его окне. На macOS/Linux создайте окружение командой `python3 -m venv .venv`,
затем используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.

В браузере доступны поиск (в том числе без учёта регистра кириллицы), фильтр
ближайших ТО, добавление техники, карточка машины, обновление наработки,
запись ремонта и сумма расходов. У терминального поиска сохраняется ограничение
SQLite по регистру кириллицы. Введённые на сайте данные сохраняются в тот же
`journal.db`. Для тестирования с другой базой задайте переменную `JOURNAL_DATABASE`.

Веб-версия защищена одной общей учётной записью. Все вошедшие работают
с одним журналом. Перед запуском настройте логин и пароль, как описано ниже. Для хостинга предусмотрена фабрика
`create_app()` в `app.py`; секрет сессии задаётся через `SECRET_KEY`.
Встроенный сервер Flask используется только локально.

`templates/` содержит HTML-шаблоны, `static/style.css` — оформление,
`app.py` — обработчики страниц и форм. Они используют функции из `journal.py`.

## Терминальная версия

Нужен Python 3.10 или новее с модулем SQLite (входит в обычную установку
Python). Только для терминальной версии дополнительные пакеты не требуются.

Скачайте проект, распакуйте архив и откройте папку в терминале или VS Code:

```text
python journal.py
```

На Windows можно открыть `Start.cmd` двойным щелчком. Он ищет подходящий
Python по порядку: `.venv\Scripts\python.exe` внутри проекта, `py -3`, затем
`python`. Если интерпретатор не найден или его версия ниже 3.10, появится
сообщение со ссылкой на установку. Фиксированных путей к чужому компьютеру нет.

На macOS/Linux используйте `python3 journal.py`. `Start.cmd` предназначен
только для Windows. База `journal.db` создаётся автоматически рядом с программой.

## Возможности

- Добавление техники с уникальным номером погрузчика.
- Учёт моточасов и предупреждение о наступившем ТО.
- Предупреждение «Скоро ТО» при остатке от 1 до 50 моточасов включительно.
- Список ближайших ТО, отсортированный по срочности.
- Запись ремонта, работ, запчастей и стоимости в целых рублях.
- Просмотр истории ремонтов, общей суммы затрат и обновление плана ТО.
- Поиск техники по модели или номеру погрузчика.
- Сохранение в SQLite: данные остаются после закрытия программы.

План ТО задаётся вручную в абсолютных моточасах. Например, при текущих
1200 м/ч и следующем ТО на 1500 м/ч программа показывает остаток 300 м/ч.
Обычная запись ремонта не переносит срок ТО. Это локальный журнал,
он не отправляет уведомления и не предназначен для одновременной работы пользователей.

Поиск выполняется по части текста. Регистр латинских букв не важен;
для кириллицы регистр должен совпадать (ограничение встроенного `lower()` SQLite).
Стоимость вводится в целых рублях, а хранится в копейках.

4. Откройте пункт 1: до ТО должно остаться 300 м/ч.
5. В пункте 3 запишите замену фильтра на 1210 м/ч за 1500 рублей.
6. В пункте 4 проверьте историю, затем перезапустите программу.

## Как устроен код

- `open_database()` создаёт таблицы при первом запуске.
- `add_machine()` добавляет технику. Знаки `?` в SQL отделяют данные от команды.
- `record_repair()` сохраняет ремонт и новую наработку одной транзакцией.
- `service_status()` рассчитывает остаток моточасов до обслуживания.
- `search_machines()` ищет технику по части модели или номера погрузчика.
- `main()` показывает меню и вызывает функции.

Для начала измените приветствие внутри `main()` и запустите программу снова.
Затем разберите `service_status()`: это первая небольшая функция для изучения.

## Проверка

```text
python -m unittest -v
```

На Windows также можно использовать `py -3 -m unittest -v`,
на macOS/Linux — `python3 -m unittest -v`.

Для всех тестов сначала установите `requirements.txt` и запускайте
`.venv\Scripts\python.exe -m unittest -v` (на Windows).
Без Flask доступны исходные тесты: `python -m unittest test_journal -v`.

В проекте 20 тестов: статусы ТО и границы предупреждения, уникальность номера,
запись ремонта и проверка некорректных данных, поиск, порядок ближайших ТО,
сумма расходов и вывод истории. Тесты используют базу в памяти и не изменяют
ваш журнал. Дополнительно проверяются веб-формы, сохранение и поиск, ошибки
ввода, защита форм и экранирование HTML.

## Вход и удаление техники

Вход обязателен для просмотра и изменения журнала. Пока учётная запись не
настроена, приложение показывает страницу настройки с кодом 503.

Настройте её локально командой:

```text
.venv\Scripts\python.exe configure_access.py
```

На хостинге используйте `.venv/bin/python configure_access.py`.
Логин задаётся при настройке, пароль вводится скрыто дважды. Хранится только
его хеш в `instance/auth.json`, который исключён из Git и архивов исходников.
После настройки перезапустите сервер (Reload на хостинге).
Вместо файла можно задать JOURNAL_USERNAME и JOURNAL_PASSWORD_HASH.
Не пересылайте открытый пароль в чат и не включайте файл доступа в репозиторий.

Сессия действует до выхода или до 8 часов, закрытие браузера само по себе
не гарантирует выход. Кнопка «Выйти» завершает сессию.
Для смены учётной записи повторите настройку. Чтобы завершить уже выданные
сессии на хостинге, смените SECRET_KEY или instance/session.key и перезапустите сервер.

В карточке есть удаление техники. Требуется ввести её номер погрузчика;
при удалении вместе с карточкой удаляется вся история ремонтов. Встроенной
корзины нет. Перед удалением нужных записей сделайте резервную копию базы.

Денежные поля из веб-интерфейса убраны. Новые ремонты через веб сохраняются
без стоимости; прежние значения в базе не изменяются. Терминальная версия
пока сохраняет прежние поля.

На хостинге `wsgi.application` использует отдельную базу `instance/public.db`.
Локальная `journal.db` туда не переносится. Подробности — в DEPLOY.md.

## Публикация на GitHub

Публикуйте только исходники и документацию:

```text
.gitignore
journal.py
test_journal.py
README.md
Start.cmd
Start-Web.cmd
requirements.txt
app.py
test_web.py
templates/
static/
wsgi.py
test_public.py
test_auth.py
configure_access.py
DEPLOY.md
```

Не загружайте `journal.db`, другие базы и их служебные файлы,
`CHAT_CONTEXT.md`, `__pycache__`, `.venv`, `instance/`, `.env*` и резервные копии `*.bak`.
Они исключены в `.gitignore`, но при ручной загрузке через сайт GitHub
нужно самостоятельно выбрать только файлы и папки выше: `.gitignore`
не фильтрует файлы в веб-форме. Уже отслеживаемые Git файлы он тоже не исключает.

Перед отправкой через Git проверьте `git status --short` и
`git ls-files`: личных файлов среди отслеживаемых быть не должно.
Для резервной копии данных закройте программу и сохраните `journal.db`
отдельно от публичного репозитория.

На GitHub Pages Python-программа не запускается; исходники можно опубликовать
отдельным репозиторием, а в портфолио добавить описание и ссылку.
