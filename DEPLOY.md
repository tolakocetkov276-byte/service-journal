# Публикация общего журнала

Без регистрации: все посетители могут читать и изменять общие записи.
Используйте только вымышленные данные. Локальная база journal.db не нужна
на хостинге и не должна загружаться. Удаления в интерфейсе нет.

## 1. GitHub

Создайте публичный репозиторий service-journal. Загрузите исходники из
подготовленного архива, сохранив папки templates и static. Не загружайте
сам ZIP как замену исходникам. Проверьте отсутствие journal.db,
CHAT_CONTEXT.md, instance, .venv, __pycache__ и *.bak.

## 2. PythonAnywhere

Создайте бесплатный аккаунт Beginner на pythonanywhere.com.
В Bash-консоли клонируйте репозиторий (замените USERNAME своим логином GitHub):

```sh
git clone https://github.com/USERNAME/service-journal.git
cd service-journal
python3.10 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest -v
```

Используйте установленную на хостинге версию Python 3.10 или новее;
версия окружения должна совпадать с выбранной версией веб-приложения.

На вкладке Web создайте приложение через Manual configuration, выбрав
соответствующую версию Python. Укажите путь виртуального окружения:
`/home/YOUR_USERNAME/service-journal/.venv`.

В WSGI configuration file оставьте следующий код, заменив YOUR_USERNAME
на имя аккаунта PythonAnywhere:

```python
import sys

project = '/home/YOUR_USERNAME/service-journal'
if project not in sys.path:
    sys.path.insert(0, project)

from wsgi import application
```

Файл конфигурации хостинга не должен называться wsgi.py внутри папки проекта:
он импортирует уже существующий модуль проекта wsgi.py.

Для статических файлов добавьте mapping URL `/static/` на каталог
`/home/YOUR_USERNAME/service-journal/static`. Включите HTTPS / Force HTTPS
и нажмите Reload. Cookie сессии публичной версии работает только через HTTPS.

При первом запуске автоматически появятся:
- `instance/public.db` — отдельная общая база, сначала пустая;
- `instance/session.key` — постоянный ключ сессии, если SECRET_KEY не задан.

Оба файла остаются на хостинге и не входят в Git. Не удаляйте instance
при обновлении кода. Для резервной копии остановите запись данных и
скопируйте public.db в непубличное место. Не переносите туда journal.db.

## 3. Проверка после публикации

1. Откройте HTTPS-адрес и убедитесь, что виден текст об общем журнале.
2. Добавьте вымышленную машину DEMO-01 с 1470 м/ч и ТО на 1500.
3. Проверьте фильтр ТО, поиск и карточку, запишите учебный ремонт.
4. Откройте сайт в другом браузере: записи должны быть общими.
5. Нажмите Reload в панели хостинга и проверьте сохранность записей.

Это открытая учебная демонстрация без защиты от массового добавления
данных. Для реальной эксплуатации потребуются аккаунты и ограничения доступа.
На бесплатном плане проверяйте срок активности сайта в панели и продлевайте
его вовремя. GitHub Pages для Flask не подходит.
